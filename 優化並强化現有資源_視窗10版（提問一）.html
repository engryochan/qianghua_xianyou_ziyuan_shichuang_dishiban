為何不做「一鍵最強版」

「最強」沒有明確定義。網路上常見的一鍵優化腳本，多半靠關遙測、關服務、改登錄檔，常讓系統更新或軟體出問題，而且難以還原。所以我的設計是：

  1. 先診斷，找出真正的問題，再逐項修正。
  2. 每個動作都是獨立開關，可用 -WhatIf 預演。
  3. 會改變狀態的步驟先備份，例如系統還原點、R 套件清單、pip freeze。
  4. 完全不碰遙測、Defender、服務與登錄檔「調校」。

function Section {
    param([string]$Name)

    $line = ""
    $line += "`r`n"
    $line += ("=" * 78)
    $line += "`r`n"
    $line += $Name
    $line += "`r`n"
    $line += ("=" * 78)

    $line | Tee-Object -FilePath $Report -Append
}

Get-CimInstance Win32_LogicalDisk -Filter "DriveType=3" |
    Select-Object DeviceID,
        VolumeName,
        FileSystem,
        Size,
        FreeSpace |
    ForEach-Object {

        $SizeGB = [math]::Round($_.Size / 1GB,2)
        $FreeGB = [math]::Round($_.FreeSpace / 1GB,2)
        $FreePct = if ($_.Size -gt 0) {
            [math]::Round(($_.FreeSpace / $_.Size) * 100,2)
        } else {
            0
        }

        [PSCustomObject]@{
            Drive = $_.DeviceID
            Volume = $_.VolumeName
            FileSystem = $_.FileSystem
            SizeGB = $SizeGB
            FreeGB = $FreeGB
            FreePercent = $FreePct
        }
    } |
    Format-Table -AutoSize |
    Out-String |
    Tee-Object -FilePath $Report -Append

function Add-Result {
    param(
        [string]$Category,
        [string]$Name,
        $Value,
        [string]$Status = "INFO",
        [string]$Recommendation = ""
    )

    $item = [pscustomobject]@{
        Category = $Category
        Name = $Name
        Value = if ($Value -is [string]) { $Value } else { ($Value | Out-String).Trim() }
        Status = $Status
        Recommendation = $Recommendation
    }

function Invoke-Safe {
    param(
        [string]$Name,
        [scriptblock]$Script,
        [string]$Recommendation = ""
    )

    try {
        $value = & $Script 2>&1
        Add-Result -Category "Command" -Name $Name -Value $value -Status "OK" -Recommendation $Recommendation
        return $value
    }
    catch {
        Add-Result -Category "Command" -Name $Name -Value $_.Exception.Message -Status "ERROR" -Recommendation $Recommendation
    }
}

9. Red-team / Critic / Blindspot 审查

Red-team：攻击环境本身

重点检查：

  • 是否存在多个 python.exe、多个 Rscript.exe。
  • IDE 使用的解释器是否与终端一致。
  • PATH 是否包含旧版 R、旧版 Java、旧版 CUDA。
  • 是否把凭据写入 .Rhistory、.Renviron、.env 或 Notebook。
  • 是否让敏感数据进入云同步目录。
  • 是否为 DuckDB、StarRocks、MariaDB 保留备份。
  • 是否存在未经维护的全局包。

执行：

where.exe python
where.exe Rscript
where.exe git
where.exe quarto

Get-Command python,Rscript,git,quarto -All -ErrorAction SilentlyContinue |
    Select-Object Name, Source, Version

Critic：批判“优化”的真实性

不要用这些指标判断环境变强：

安装包数量更多
磁盘中缓存更多
IDE 启动更快但结果不可复现
CPU 长期 100%
内存长期接近满载
模型训练时间下降但验证集泄漏
AUC 上升但时间切分错误
C-index 小于 0.5 却直接宣布模型失败

你项目中已经记录了一个典型问题：XGBoost 生存模型的 C-index 约为 0.299，这可能是风险分方向和 C-index 计算方向相反，而不是模型没有预测能力。此类指标必须同时检查标签定义、事件方向、时间切分和 reverse=TRUE 等实现细节。 pplxfilegitgateway-projectfiles-prod-use1.s3.us-east-1.amazonaws

Kill switch：出现这些情况立即停止自动优化

如果出现以下任一情况，不要继续自动安装或升级：

  • 系统盘剩余空间低于 15%。
  • 可用内存低于 4 GB。
  • R 包出现 DLL 锁定、00LOCK 或 TMB 版本冲突。
  • Python 环境中出现多个解释器但未确定项目解释器。
  • 数据库连接仍在运行而你准备删除缓存或重装驱动。
  • 训练数据和测试数据存在主体或时间泄漏。
  • 风控标签没有人工复核和回滚机制。
  • 系统处于生产任务、数据库写入或模型发布阶段。

Blindspot：容易被忽略的地方

  • 软件安装成功不等于 PATH 正确。
  • 包版本正确不等于 ABI、编译器和 DLL 兼容。
  • 机器有大量内存不等于单个 DataFrame 能安全装下。
  • 结果有高 AUC 不等于不存在时间泄漏。
  • 风险分数高不等于可以自动冻结账户。
  • 钱包 Join 覆盖率为 0 时，钱包特征应禁用，而不是用 0 静默填充。
  • Parquet 压缩后体积小，不代表列类型、时区和金额精度正确。
  • COUNT(*) 正确，不代表唯一键没有重复。

Red Team / Critic / Kill Critic / Blindspot / Action Plan 分析

總結結論

Windows 10（目前時間 2026 年 9 月）主流支援已結束（2025 年 10 月），但消費者 ESU 已延長至 2027 年 10 月。可以安全地用 PowerShell 做診斷與合理優化，但「強化到最強版」必須謹慎、可逆、以資料分析為優先，不能無腦關閉安全性功能或大量 debloat。

以下提供完整可執行的 PowerShell 腳本框架（分診斷 + 優化 + 資料分析強化），並附分析。

Red Team（對抗思考）

  • 診斷腳本可能洩漏敏感軟體清單（若輸出到檔案）。
  • 激進優化（關閉 Defender、大量移除 Appx、關閉 Telemetry）會增加攻擊面，尤其 Win10 已無主流更新。
  • 資料分析工具（Python/R/Anaconda）安裝後會佔用大量空間與記憶體，可能拖慢舊硬體。
  • 腳本若以 Administrator 執行且寫入錯誤路徑，有破壞系統風險。

Critic（批評）

  • 「最強版」是行銷用語，實際沒有單一最強設定。過度優化常導致不相容（Office、瀏覽器、驅動、分析套件）。
  • 許多網路上流傳的 debloat 腳本在 2026 年已過時，可能破壞 ESU 相關元件或 Copilot/Edge。
  • Win10 硬體老化，優化收益有限，真正瓶頸常是 RAM/SSD/CPU，而非設定。

Kill Critic（反駁）

  • 合理診斷 + 針對性優化（清理、高效能電源、安裝最新資料分析工具）確實能提升穩定性與分析效率。
  • 使用官方 winget + 內建 cmdlet 比第三方優化器更安全可控。
  • 只要先建立還原點、輸出報告、分步執行，風險可控。

Blindspot（盲點）

  • 企業/受管裝置可能有 Group Policy 限制，腳本會失敗。
  • 本機帳戶 vs Microsoft 帳戶影響部分功能。
  • 資料分析環境需要虛擬環境（venv/conda），單純系統優化不夠。
  • 硬碟空間不足時，安裝 Anaconda/Python 套件會失敗。
  • 語言/地區設定可能影響 winget 來源。

Action Plan（行動計畫）

function Invoke-Safe($Desc, $Action) {
  Write-Host "`n=== $Desc ===" -ForegroundColor Cyan
  if (-not $Apply) {
    Write-Host "[未執行] 加 -Apply 才會執行" -ForegroundColor Yellow
    return
  }
  try {
    & $Action
    Write-Host "完成" -ForegroundColor Green
  } catch {
    Write-Warning "失敗：$_"
  }
}

redteam/ 邊界審計與極限漏洞排查 (Adversarial Audit & Throttling Assessment)

在高效能數據分析與量化計算情境下，Windows 10 預設運作環境存在多項隱蔽的效能瓶頸與資源干擾：

  1. 檔案 I/O 即時掃描干擾：Windows Defender 的 Real-Time Protection 會在每次 R、Python 或資料庫讀寫大量 CSV、Parquet、RDS 或 SQLite 快取時進行強行攔截與哈希比對，導致巨量資料集（GB/TB 級）讀取延遲增加 15%–40%。
  2. CPU 動態降頻與 Core Parking：預設的省電策略會將部分邏輯核心強行休眠，並在多執行緒矩陣運算（如 OpenBLAS / MKL）啟動時產生毫秒級的推升延遲。
  3. 分頁檔案（Pagefile）與記憶體碎片：預設的動態分頁機制會在記憶體用量暴增時（如載入巨量 DataFrame）引發劇烈的硬碟 I/O 換頁震盪。
  4. 網路堆疊 TCP 延遲：本地資料庫（PostgreSQL、MariaDB、StarRocks 等）連接使用預設 TCP/IP 設定時，會因為 Nagle 演算法與受限的 TCP 受理視窗而吞吐受限。

critic/ 系統痛點與原生缺陷批判 (Systemic Flaws & Bottleneck Diagnostics)

  • SysMain (Superfetch) 與 Windows Search 索引：無差別地對磁碟進行背景掃描，極易鎖定大數據工作目錄，奪取 NVMe SSD 的隨機讀寫 IOPS。
  • 預設單執行緒 BLAS/LAPACK：原生 R 與 Python 在 Windows 下預設往往僅呼叫單執行緒 BLAS，無法發揮多核心 CPU 的向量化計算能力。
  • WSL2 記憶體吃滿不釋放：WSL2 預設會無節制吞噬高達 80% 的實體 RAM，且 Linux 內部釋放記憶體後，Windows 主機端的 VHDX 佔用不會自動歸還。
  • 背景更新與診斷遙測（Telemetry）：Windows 遙測服務在背景佔用 CPU 週期與網路頻寬，影響高頻率腳本執行的穩定度。

killcritic/ 提速粉碎方案 (Decisive Elimination Strategy)

  1. 解鎖「卓越效能模式」（Ultimate Performance Power Plan）：全面禁止 CPU Core Parking、強制維持 CPU 在最高時脈運作。
  2. 實施精準的防毒排除（Defender Path Exclusions）：將 Python/R 執行檔、專案路徑、WSL 磁碟與臨時暫存目錄徹底排除在即時掃描之外。
  3. 優化 Windows 系統 TCP/IP 網路參數：啟用 CTCP 壅塞控制、優化 Window Auto-Tuning，極限化本地與近端資料庫連線吞吐量。
  4. 全域注入多執行緒環境變數：確保 OpenBLAS、Intel MKL、OpenMP 在多核心環境下自動全速全執行緒運轉。
  5. 部署自動化 .wslconfig 管控機制：精確劃分 WSL2 的 CPU/RAM 資源邊界，防止 WSL2 與 Windows 爭奪記憶體。

blindspot/ 數據工程與分析專屬盲點 (Analytics Infrastructure Blind Spots)

  • Git 260 字元路徑限制 (LongPaths)：深度嵌套的數據專案或套件依賴易觸發 Windows MAX_PATH 錯誤。
  • R / Python 專案臨時快取目錄（TEMP/TMP）：預設放在系統 C 盤，若 C 盤非極速 SSD，會直接打爛數據處理瓶頸；應導向最高速的 NVMe 磁碟或 RamDisk。
  • RStudio / Positron / VS Code 檔案監控限制：IDE 背景的 File Watcher 監視過多數據檔案時，會導致 CPU 無預警佔用高達 100%。

三、強化（Harden）腳本 — 自動套用建議（含 Dry-run 與互動確認）

設計原則：先做 dry-run（模擬），列出將要變更的項目；管理員確認後才執行。腳本包含：啟用防火牆、封鎖入站 RDP、關閉 SMBv1、啟用 BitLocker（若支援）、強化 Defender、設定 Windows Update 自動安裝、強化本機密碼與鎖定策略、關閉不必要服務、啟用受限管理員權限原則等。

# Save as: Harden-Win10-Apply.ps1
# Run as Administrator

param(
    [switch]$ApplyChanges  # 若指定 -ApplyChanges 則實際套用，否則僅列出（dry-run）
)

function Report($msg){ Write-Host "[*] $msg" -ForegroundColor Cyan }

Report "開始系統強化流程 (ApplyChanges = $ApplyChanges)"

# 1. Enable Firewall profiles
$fwCmds = @(
    'Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled True',
    'Set-NetFirewallProfile -Profile Domain,Public,Private -DefaultInboundAction Block -DefaultOutboundAction Allow'
)
if ($ApplyChanges) {
    Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled True
    Set-NetFirewallProfile -Profile Domain,Public,Private -DefaultInboundAction Block -DefaultOutboundAction Allow
    Report "防火牆已啟用並設定預設入站封鎖"
} else { $fwCmds | ForEach-Object { Report "DRYRUN: $_" } }

# 2. Block inbound RDP by default (allow only via specific rule if needed)
$rdpCmd = 'Set-NetFirewallRule -DisplayName "Remote Desktop - User Mode (TCP-In)" -Enabled False -ErrorAction SilentlyContinue'
if ($ApplyChanges) {
    Get-NetFirewallRule -DisplayName '*Remote Desktop*' -ErrorAction SilentlyContinue | Set-NetFirewallRule -Enabled False
    Report "已停用預設 Remote Desktop 防火牆規則"
} else { Report "DRYRUN: 停用 Remote Desktop 防火牆規則" }

# 3. Disable SMBv1
$smbCmd = 'Disable-WindowsOptionalFeature -Online -FeatureName SMB1Protocol -NoRestart'
if ($ApplyChanges) {
    Disable-WindowsOptionalFeature -Online -FeatureName SMB1Protocol -NoRestart -ErrorAction SilentlyContinue
    Report "已停用 SMBv1（如支援）"
} else { Report "DRYRUN: $smbCmd" }

# 4. Enforce Windows Update automatic install (requires PSWindowsUpdate module for immediate install)
$wuCmds = @(
    'Install-Module -Name PSWindowsUpdate -Force -Scope AllUsers',
    'Import-Module PSWindowsUpdate',
    'Get-WindowsUpdate -Install -AcceptAll -AutoReboot'
)
if ($ApplyChanges) {
    if (-not (Get-Module -ListAvailable -Name PSWindowsUpdate)) {
        Install-Module -Name PSWindowsUpdate -Force -Scope AllUsers
    }
    Import-Module PSWindowsUpdate
    Get-WindowsUpdate -Install -AcceptAll -AutoReboot
    Report "已嘗試安裝可用的 Windows Update 更新"
} else { $wuCmds | ForEach-Object { Report "DRYRUN: $_" } }

# 5. Enable Windows Defender real-time & Controlled Folder Access & Tamper protection note
$defCmds = @(
    'Set-MpPreference -DisableRealtimeMonitoring $false',
    'Set-MpPreference -EnableControlledFolderAccess Enabled'
)
if ($ApplyChanges) {
    try {
        Set-MpPreference -DisableRealtimeMonitoring $false
        Set-MpPreference -EnableControlledFolderAccess Enabled
        Report "Defender 即時保護與受控資料夾存取已啟用（如支援）"
    } catch { Report "Defender cmdlet 無法執行或權限不足" }
} else { $defCmds | ForEach-Object { Report "DRYRUN: $_" } }

# 6. Enable BitLocker on OS drive (requires TPM and user consent)
$bitCmd = 'manage-bde -on C: -RecoveryPassword'
if ($ApplyChanges) {
    try {
        $bl = Get-BitLockerVolume -MountPoint C: -ErrorAction Stop
        if ($bl.ProtectionStatus -eq 'Off') {
            manage-bde -on C: -RecoveryPassword
            Report "已啟用 BitLocker（請完成恢復金鑰備份流程）"
        } else { Report "BitLocker 已啟用" }
    } catch { Report "BitLocker cmdlet 無法執行或系統不支援 TPM/BitLocker" }
} else { Report "DRYRUN: $bitCmd (需手動確認 TPM 與恢復金鑰備份)" }

# 7. Local account lockout & password policy (example: lockout after 5 invalid attempts)
$pwCmds = @(
    'net accounts /minpwlen:12',
    'net accounts /maxpwage:60',
    'net accounts /lockoutthreshold:5',
    'net accounts /lockoutduration:30'
)
if ($ApplyChanges) {
    net accounts /minpwlen:12
    net accounts /maxpwage:60
    net accounts /lockoutthreshold:5
    net accounts /lockoutduration:30
    Report "已設定本機密碼與鎖定策略"
} else { $pwCmds | ForEach-Object { Report "DRYRUN: $_" } }

# 8. Disable unnecessary services (示例：Telnet, RemoteRegistry) - 先列出再停用
$svcCandidates = @('Telnet','RemoteRegistry')
foreach ($s in $svcCandidates) {
    $svc = Get-Service -Name $s -ErrorAction SilentlyContinue
    if ($svc) {
        if ($ApplyChanges) {
            Set-Service -Name $s -StartupType Disabled -ErrorAction SilentlyContinue
            Stop-Service -Name $s -Force -ErrorAction SilentlyContinue
            Report "已停用服務 $s"
        } else { Report "DRYRUN: 將停用服務 $s" }
    } else { Report "服務 $s 不存在" }
}

# 9. Restrict local admin usage: enable UAC Admin Approval Mode (registry)
$uacCmd = 'Set-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" -Name "ConsentPromptBehaviorAdmin" -Value 2'
if ($ApplyChanges) {
    Set-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" -Name "ConsentPromptBehaviorAdmin" -Value 2
    Report "已強制 UAC 管理員提示"
} else { Report "DRYRUN: $uacCmd" }

# 10. Final note & reboot prompt
if ($ApplyChanges) {
    Report "強化已套用。建議立即重新啟動系統以完成部分變更。"
} else {
    Report "Dry-run 完成。若要實際套用，請以 -ApplyChanges 參數重新執行此腳本。"
}

四、針對「分析數據的軟體/套件」的專項強化建議

  • 網路隔離：若處理敏感資料，將分析主機放在受控子網或使用防火牆規則限制外部連線。

  1. 備份：建立系統還原點與重要資料備份。

  • SMBv1：停用後若有舊設備或 NAS 只支援 SMBv1，請先確認相容性。
  • RDP：若需要遠端管理，建議改用 VPN + 限制來源 IP 的防火牆規則，或使用跳板主機。
  • 服務停用：停用系統服務前請確認依賴關係，避免造成應用中斷。

這是為 Windows 10 數據分析工作站設計的「診斷 + 最強優化」完整方案。我給你兩個腳本，一個只讀診斷，一個可逆優化。

1. Redteam / 對抗視角

你的數據分析環境最大的敵人不是算力不足，是環境污染。常見被攻擊點：多版本 Python/R 衝突、PATH 被污染、舊版 pip 包有 CVE、OneDrive 鎖死你的數據集、Defender 即時掃描把 pandas.read_csv 拖慢 10倍、自動更新重啟中斷你跑了 8小時的模型。

2. Critic / 批判

Win10 預設值是為 Office 上網設計的，不是為 Data Science。省電模式限制 CPU 睿頻、視覺特效吃掉 1-2GB RAM、預裝 30+ 個 UWP 垃圾、Pagefile 自動管理在 16GB RAM 機器上會導致 OOM、長路徑限制讓 Python 建環境直接失敗。

3. KillTactic / 要殺掉什麼

  1. 殺啟動項： Teams, OneDrive, Adobe, Spotify 開機自啟動
  2. 殺視覺特效： 動畫、透明、縮圖快取
  3. 殺節能限制： 平衡電源計劃、USB 選擇性暫停、PCIe 節能
  4. 殺掃描干擾： 對 D:\Data, .conda, .venv 建立 Defender 信任區，不是關掉 Defender

4. Blindspot / 盲點

90% 的人只裝 Python，忽略了 4 個真正的瓶頸： * WSL2 + Docker 才是現在數據分析的主戰場，原生 Win10 跑 Polars/Arrow 慢 30% * Long Path 沒開，pip install 會莫名失敗 * Pagefile + RAM 診斷，你以為你有 32GB，其實被 Chrome 吃光，模型被迫用磁碟 * 硬體加速排程 沒開，NVIDIA GPU 在 Win10 預設是被系統卡住的

施工途中發現並修正的五個真實 bug

1. R 堆疊第一次整批 74 個套件，一個都沒裝成。

根因不是網路、不是權限，也不是防毒：清單裡的 qs、fastshap、vip 已從 CRAN 封存。而 pak 的求解器是全域的——只要清單裡有一個套件找不到，它會把整批 74 個全部標成 dependency conflict。錯誤訊息長得像「所有套件都有依賴衝突」，很容易誤判成 R 版本太新或鏡像壞掉。

修法：換成 qs2 / shapviz + kernelshap；安裝前用 available.packages() 重新核對，不相信寫死的清單；改成每批 12 個、整批失敗退回逐一安裝。重跑後 78/78 全裝成——第 1、3 批在 pak 下仍失敗，逐一退回機制把它們補上了。

2. .Rprofile 不該改變分析行為。

我上一輪寫入的 .Rprofile 含 OMP_NUM_THREADS、TZ、warnPartialMatchArgs。.Rprofile 是單機獨有的檔案，把行為設定放進去，等於讓同一份腳本在本機與同事機器跑出不同結果，且極難追查。改為只保留影響「套件怎麼裝」的設定。執行緒請在腳本內明示 setDTthreads()、arrow::set_cpu_count()；版本鎖定用 renv::init()。

3. Rtools 偵測路徑錯了，而且根本不該進 PATH。

Rtools4x 的 gcc 在 x86_64-w64-mingw32.static.posix\bin，不在 usr\bin（那裡只有 make / sh），所以原本的探測把「已安裝」誤報成「沒安裝」。改以登錄機碼 HKLM\SOFTWARE\R-core\Rtools 為準。

同時停止把 Rtools 加進 PATH：R 是靠登錄機碼找工具鏈的——實測 R CMD SHLIB 在 PATH 沒有 Rtools 的情況下編譯成功（gcc 14.3.0）。而 rtools\usr\bin 內含 sh.exe / find.exe / sort.exe，排進 PATH 會蓋掉同名 Windows 內建指令。

另記一項容易誤判的事實：Rtools 版本號不等於 R 次版本。R 4.6 用的就是 Rtools45，CRAN 並未發行 rtools46。能不能編譯要用 R CMD SHLIB 實測，不能由版本號推論。

4. PATH 判定看錯對象。

原本用 Get-Command 查目前行程的 $env:PATH，但那是行程啟動時複製的快照。剛改過 PATH 的機器，舊 session 會把已經修好的項目報成「不在 PATH 上」，讓人白忙一場。改為讀登錄檔中持久化的 Machine + User PATH，也就是「重開視窗後」的真實狀態。

5. uv 建立的 venv 讀不到套件清單。

uv 的 venv 刻意不安裝 pip，所以 python -m pip list 回空清單，把 149 個套件的完整環境誤報成空環境。改用標準庫 importlib.metadata。附帶一個 Windows 特有的坑：這段 Python 程式碼內不能有引號——PowerShell 5.1 把參數傳給原生程式時會把引號吃掉，d.metadata["Name"] 會變成 d.metadata[Name] 而拋 NameError。用不需引號的 d.name。

還有一個誤報：把 uv 和 pip 列進 venv 的「應有套件」清單。uv 是獨立執行檔，pip 本就不該在 uv venv 裡。
