### 1.2 **陷阱：Windows Update 提供的那個驅動不該裝**

| | 版本 | 日期 | 供應商 |
|---|---|---|---|
| 本機已安裝 | **9.1.412.2015** | 2015-03-31 | Microsoft 內建 |
| WU 提供 | 9.1.409.2015 | 2015-04-09 | Realtek |

版本號 412 > 409，但 Windows 判斷新舊是**先比日期再比版本**，所以它認為自己較新。

這張 Realtek 以太網卡是**目前唯一在用的連線**（硬體識別碼
`PCI\VEN_10EC&DEV_8168&SUBSYS_012310EC&REV_2B`），換驅動期間會斷線、不相容則
可能完全失去連線，而本機是受管理的公司資產。**建議交 IT，取得順序為整機／板卡廠
原廠包（OEM）優先，其次 Realtek 通用包。**

### 6.1 **為何不能一律升級——清單自己給了反證**

核心環境的過時清單裡有這一行：

```
cffi    2.0.0    2.1.1    wheel
```

而本倉庫 `CLAUDE.md` 早已記載這組互斥：

> `gevent==26.9.0` vs `cffi==2.0.0`：gevent 在 win32 要 `cffi>=2.1.1`
> （`ccxt` 也死釘 2.0.0）。**這兩個釘選單獨放在一起就無解。**

**所以 `cffi` 顯示「過時」不是缺陷，是刻意釘住的結果**——`ccxt` 需要 2.0.0，
當初正是為此把 `gevent` 外移到 `rl` 衛星環境。**把它升到 2.1.1 會當場弄壞 `ccxt`。**

同理，清單裡還有數個落在既有互斥上的套件：`transformers`（`flair` 要 `<5`）、
`plotly`（`evidently` 要 `<6` 而 `dalex` 要 `>=6`，所以分住 `mlops` 與 `xai`）、
`toolz`（`gluonts` 要 `<1`）、`fsspec`／`s3fs`（版本須同步）。

> **「過時」在這個環境裡不等於「該升」。** 這 1,375 個套件是一個**求解過的約束
> 系統**，不是一堆各自獨立的軟件。本倉庫最痛的一課正是：那份
> `python-ds-requirements.lock.txt` 從第一行就無解，因為 **pip 安裝時不做全域
> 求解**，衝突只印警告然後照裝。盲目升級等於把那個狀態重新製造一次。

### 6.2 安全的升級路徑（若先生要推進）

**不要** `uv pip install --upgrade` 全體。正確做法是沿既有架構走：

1. 改 `env/python-ds-core.in`（核心約束檔，698 個 `==` + 28 個 `>=`），
   **只放寬打算升的那幾個**，互斥項保持釘住。
2. 用 **uv 重建**環境——uv 的求解器**是全域的**，衝突會在安裝前就報出來，
   不會像 pip 那樣先裝壞再警告。
3. 以 `診斷操作系統\Run_Full_Regression.ps1` 為驗收閘，**八節必須 0 失敗**
   （派森 15/15、R 10/10、五衛星、flair 命名實體辨識、CmdStan 編譯擬合、
   Quarto 算繪、六個核心）。
4. 通過才 `uv pip freeze` 更新 `env/python-ds-verified.lock.txt`。

**驗收標準是「跑出結果」，不是「裝成功」**——這是本倉庫第一條教訓。

### 6.3 真正值得優先升的，是有已知缺陷者

與其追 347 個版本號，更有價值的是針對**已知會出錯**者。目前已記載的一例已處理：
`lightgbm` 必須 `>=4.6.0`（4.5.0 呼叫 scikit-learn 已移除的 `force_all_finite`，
依賴求解器看不到，**只有真的擬合一次才會知道**）。
