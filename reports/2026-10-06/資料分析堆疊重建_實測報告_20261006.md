## 一、最重要的發現：那份鎖版檔無法重建任何環境

第一次照 CLAUDE.md 的既定流程做
（`uv venv` → `uv pip install -r env/python-ds-requirements.lock.txt`），
在 27 秒內就失敗：

```
error: No solution found when resolving dependencies
  cause: Because boto3==1.43.98 depends on botocore>=1.43.98,<1.44.0
         and you require botocore==1.43.75 ... unsatisfiable.
```

我寫了一支可稽核的迭代鬆綁器（`診斷操作系統/Reconcile_PythonLock.py`，
每一次改動都寫進 `lock-reconciliation.json`）把矛盾全部挖出來。
**共六處內部矛盾，其中五處是真正不可化解的互斥：**

| # | 矛盾 | 性質 |
|---|---|---|
| 1 | `boto3==1.43.98` 要 `botocore>=1.43.98`，鎖版檔釘 `botocore==1.43.75` | 版本漂移 |
| 2 | `dalex` 要 `plotly>=6`；`evidently` 所有版本要 `plotly<6` | **互斥** |
| 3 | `flair` 所有版本要 `transformers<5`；鎖版檔釘 `transformers==5.17.0` | **互斥** |
| 4 | `gevent==26.9.0` 在 win32 要 `cffi>=2.1.1`，鎖版檔釘 `cffi==2.0.0`（`ccxt` 也死釘 2.0.0） | **互斥** |
| 5 | `gluonts` 所有版本要 `toolz<1`；鎖版檔釘 `toolz==1.1.0` | **互斥** |
| 6 | `s3fs==2026.9.0` 要 `fsspec>=2026.9.0`，鎖版檔釘 `fsspec==2026.6.0` | **互斥** |

第 4 項值得單獨講：`gevent==26.9.0` 加 `cffi==2.0.0` 這**兩個釘選單獨放在一起
就已經無解**，跟我的任何鬆綁都無關。

### 根因的根因

**pip 安裝時不做全域求解。** 它逐一裝、遇到衝突只印警告然後照裝，
所以那個環境裡至少有五組套件一直跑在自己不支援的依賴版本上。
`pip freeze` 忠實地把這個**本身無解的狀態**拍成了快照。

> **推論：一份從未被真正用來重建過的鎖版檔，不是復原資產，只是一張照片。**
> 上一輪把它加進版控是對的（「復原用的鎖版檔本身也要進版控」），
> 但沒有補上最後一步——**拿它重建一次**。少了那一步，等於備份從未做還原測試。

### 兩個失敗的鬆綁策略（也都是教訓）

- **完全解除約束**會讓求解器為了閃避衝突一路回溯到史前版本：
  實測挖到 `sktime==0.8.0`（2021）與 `flair==0.2.1`（2018）。
  後者建置時直接死在
  `UnicodeDecodeError: 'gbk' codec can't decode byte 0x9d` ——
  **中文語系 Windows 下 `setup.py` 以 GBK 讀 README 爆掉**。
- **只用 `>=` 鬆綁**擋住了降版，所以遇到真互斥仍然無解。

最後採用的規則：**只在被迫時鬆綁；衝突時優先「收回鬆綁」而非丟套件；
仍無解才外移葉框架，共用底層（fsspec / toolz / cffi / plotly / transformers /
scikit-learn …）永不外移。** 42 輪後收斂。
